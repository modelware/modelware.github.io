Capabilities

From Textual Notation to Engineering Answers

Everything Sysight does is one endpoint of the model server, with the same name and parameters from every client.

Whole-Workspace Diagnostics
01

Syntax, names that do not resolve, the specification's validation rules, and asserted constraints and requirements that fail. Every file a change affects is re-checked, including files you have not opened.

Computed Values, With Units
02

Evaluate any attribute or expression in the context of an element. Results come in the unit you ask for, checked against its dimension, and appear inline in the editor beside the expressions that produce them.

Requirement Verification
03

Constraints, requirements and satisfy statements decided as satisfied, violated or undetermined, with the reason why. A requirement's verdict is visible where it is written, on hover.

SPARQL Over the Model
04

SPARQL 1.1 with entailment: asking for parts finds every kind of part. Evaluation functions bring values and verdicts into query results, and the query panel helps you write queries and charts the answers.

Safe Model Updates
05

Change the model through an update API applied as edits to the files' text, all or nothing. Each change reports its diff and the diagnostics it added and removed, with a dry run to preview it first.

Notation and RDF, Both Ways
06

Export the model as textual notation or as RDF (TriG, N-Quads, Turtle), one named graph per file, and import RDF or .kpar archives back as notation. The round trip parses to the same graphs.

In Your Editor

Write the Model. Read the Answers Beside It.

Sysight turns VS Code into a SysML v2 workbench that understands the model, not only its syntax.

  • Navigation with outline, go to definition and find references, across files and into the standard libraries.
  • Insight on hover: what an element is, what it specializes and redefines, its computed value and its verdict.

Vehicle.sysml
package VehicleModel {
    private import SI::*;

    part def Vehicle {
        // evaluates to 1130 kg
        attribute mass :> ISQ::mass = engine.mass + chassis.mass;
        part engine  { attribute mass :> ISQ::mass = 180 [kg]; }
        part chassis { attribute mass :> ISQ::mass = 950 [kg]; }
    }

    requirement def MassLimit {
        subject vehicle : Vehicle;
        require constraint { vehicle.mass <= 1500 [kg] }
    }

    part car : Vehicle;
    requirement carMass : MassLimit;                  // satisfied
    satisfy carMass by car;
}
How It Works

A SysML v2 Model, Held as a Knowledge Graph

Sysight is written in Rust and brings the semantic web foundations behind OML Code to SysML v2.

01 · Parse
Textual Notation

Your .sysml and .kerml files are read with the parser of Open-MBEE's sysml-toolkit. The standard KerML and SysML libraries are built in.

02 · Store
RDF Knowledge Graph

Each file becomes a named graph in an embedded Oxigraph store, typed by OWL ontologies shaped by the notation, so classes are named after keywords. Names re-resolve incrementally as files change.

03 · Answer
Model Server

One server per workspace serves HTTP, LSP and MCP from the same graph: diagnostics, values, verdicts and queries, plus updates written back as notation.

Why It Matters

Models That Answer Questions, Not Just Store Them

SysML v2 gives systems engineering a precise textual language and a formal semantics. Sysight puts that precision to work: the model is checked, computed and verified continuously, so problems surface while you write, not at the next review.

Because the model lives in a standard knowledge graph, the same facts that drive your editor drive your reports, your pipeline and your AI assistants. An agent that can query, evaluate and verify the model is an agent whose answers you can check.
